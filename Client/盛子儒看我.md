1. 架构概述与威胁模型 (Architecture Overview & Threat Model)
本系统采用标准的分层架构 (Layered Architecture) 设计，基于异步 ASGI 框架 FastAPI 构建。

威胁模型: 假定服务器侧为 Honest-but-curious (HbC)。即服务器严格执行协议路由逻辑，但存在潜在的数据嗅探风险。

核心准则: 实施零知识 (Zero-Knowledge) 消息传递。服务端仅作为盲中继 (Blind Relay) 执行密文的 Store-and-Forward 操作，绝不持有客户端的私钥，确保 End-to-End Confidentiality。

2. 系统分层架构模型 (Layered Architecture Demarcation)
系统自底向上划分为四层，严格遵循依赖倒置 (DIP) 与单一职责 (SRP) 原则：

2.1 数据访问与契约层 (DAL & Contracts)
Server_db.py (ORM & Relational Schema): 基于 SQLAlchemy 的声明式映射。定义了持久化数据实体 (User, Device, Friendship, OfflineMessage) 及其外键约束与级联关系。

Schema.py (DTOs & API Contracts): 基于 Pydantic 构造的 Data Transfer Objects。作为前后端交互的强类型数据校验层，确保反序列化过程中的类型安全，隔离外部脏数据。

2.2 基础设施与核心服务层 (Infrastructure & Core Services)
config.py & .env: 基于 12-Factor App 方法论的环境配置管理。通过 pydantic_settings 将敏感密钥（如 JWT Secret）与应用逻辑硬隔离。

SdbManager.py (Connection Pooling & Transaction): 数据库连接池管理器。利用 Python Context Manager (yield) 封装了 ACID 事务控制，实现 Session 的自动 commit 与异常时的安全 rollback。

limiter.py (API Throttling): 基于 slowapi 实现的全局限流器，采用 Token Bucket 或 Leaky Bucket 算法，防止接口级的暴力破解与 DoS 攻击。

ws_manager.py (WS Connection Manager): 全局单例的 WebSocket 状态机。在服务端内存中维护 UUID -> WebSocket Instance 的映射，处理长连接的生命周期管理与实时消息的 Publish/Routing。

2.3 认证与中间件层 (Authentication & Middleware)
Dependency.py (DI & Authentication Interceptors): 系统的核心依赖注入容器。包含无状态 JWT 鉴权拦截器，负责解析 HTTP Authorization Header 提取 Bearer Token，完成 Signature 校验与时效性检查，最终将认证上下文 (User UUID) 注入业务层。

2.4 业务控制器层 (Controllers / Routers)
Register.py: 负责实体注册。执行基于 Argon2 算法的密码哈希加盐操作，并生成基于 RFC 6238 的 TOTP Secret (2FA 种子)。

Login.py: 负责凭证认证。校验 Password + TOTP Code，通过验证后签发基于 RFC 7519 的无状态 JWT，并登记客户端设备的 E2EE Public Key。

Contacts.py: 社交关系图谱维护。处理状态机跃迁 (Pending -> Accept/Reject) 及基于 ACL 的关系鉴权。

Message.py: 基于 HTTP 的异步消息队列操作。提供离线密文的拉取 (Pull) 机制以及基于显式 ACK 的消息硬删除 (Hard Delete) 操作。

ChatWS.py: 全双工通信总线。处理实时在线客户端的 Event Streaming 与密文下发。

2.5 应用入口与生命周期 (Entry Point & Lifecycle)
MainServer.py: ASGI App 实例化入口。负责挂载所有 Router、配置 CORS 策略并绑定异常处理钩子。

tasks.py (Background Workers): 挂载于 FastAPI lifespan 的异步后台守护协程。使用 run_in_executor 规避 Event Loop 阻塞，定期执行 TTL (Time-To-Live) 过期离线消息的物理清除（阅后即焚落地）。

3. 核心业务链路与协议约束 (Core Workflows & Protocol Constraints)
3.1 静默拉黑与防枚举攻击 (Shadow Banning & Anti-Enumeration)
机制: 当客户端发起针对非好友或 Blocked 用户的 Send Message 请求时，服务端不返回 403 Forbidden 错误。

实现: 服务端在 Message.py 中直接 Drop 该 Payload，并动态生成伪造的 message_id (UUIDv4) 连同 200 OK 返回给发送方。以此抵御恶意客户端通过侧信道 (Side-channel) 枚举自身的拉黑状态。

3.2 消息路由与可靠投递 (Message Routing & Delivery Guarantees)
实时投递 (WebSocket): 消息优先进入 ws_manager.py 的路由表。若目标在线，直接触发 Socket Push。

离线降级 (Store-and-Forward): 若目标离线或 Push 抛出异常，密文将无缝降级并落盘至 SQLite 的 OfflineMessage 表中进行持久化排队。

消费与确认 (ACK): 接收端必须显式调用 HTTP POST /messages/ack 并携带已解密的 message_id 集合。服务端收到 ACK 后立即执行硬删除 (DELETE)，以此保证消息不被重放 (Replay) 且不在服务端冗余留存。

3.3 端到端加密责任划分 (E2EE Demarcation - Client Side)
⚠️ 客户端开发组员请注意，以下密码学逻辑必须由客户端本地实现，服务端仅做透传：

密钥生成: 客户端需在本地生成非对称密钥对 (推荐使用 Ed25519 或 RSA-2048+)。仅将其中的 Public Key 通过 /login 接口注册到服务器。Private Key 严禁离开本地安全沙箱。

会话协商: 在发起通信前，需通过 /friends/{uuid}/keys 获取对方设备的 Public Key，并通过密钥交换协议（如 X3DH）派生对称会话密钥 (Shared Secret)。

加密与完整性校验: 所有消息体必须使用带关联数据的认证加密算法 (AEAD, 如 AES-GCM 或 ChaCha20-Poly1305) 进行加密。服务端在 Message.py 接收的 ciphertext 必须是已包含 MAC/Auth Tag 的密文。
